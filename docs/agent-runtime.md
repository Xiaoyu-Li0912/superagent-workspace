- 恢复真实任务描述清理、指标方向判断、分阶段 Agent + 合并 Agent、LLM 代码审查/结果分析/方法摘要、记忆保存和检索路径；不是以外层固定脚本替代这些步骤。两阶段调度从上游 `run.py` 抽取为 `engine/scheduler.py`，保留先顺序生成草稿、再并行执行和续搜、按 journal 节点计步、普通异常续搜及默认 10 秒错峰。
- 冷启动知识库仍由上游加载；课程使用通用任务标识，不把优惠券等名字映射到人工预制方案。库中没有匹配项时按原实现返回无指导，不虚构已有知识。

## 长时间运行与网络恢复

### 2026-11-18 本机新一轮配置

用户要求先不开发续跑、不改上游算法，重新启动 10 小时实验并监督持续故障。`configs/runtime.local.yaml` 使用 500 步、36000 秒、1000 次派发、20 元，`max_unknown_calls` 从 3 提高为 1000，与调用上限一致，避免较低未知笔数独立结束搜索；不是把未知费用清零。预算仍包含全部未知/在途预留，其他网络恢复和安全限制保留。`max_unknown_calls: 0` 是严格模式，不表示关闭。下表是共享默认配置，不是该本机实验快照。

监督只读日志/事件/账本：持续约 30 分钟请求失败且没有恢复时告警，避免把单个正常长请求或暂未超过历史最佳当成卡死；预算不足、鉴权失败等需立即报告，不自动无限重启。只能尽力恢复和监督，不能保证服务可用或必跑满时间，不读取最终 test。实际配置以新 run 的 `runtime.json` 为准。

| 配置项 | 当前值 | 含义 |
|---|---:|---|
| `steps` / `time_limit_seconds` | 100 / 28800 | 最多 100 个上游 journal 步数、8 小时搜索窗口，不等于 100 个成功模型 |
| `max_calls` / `budget_rmb` | 400 / 20 | 所有 Agent 和网络重试共享的派发次数、结算加预留上限，先到者限制运行 |
| `max_output_tokens` / `request_timeout_seconds` | 32768 / 1200 | 输出总 token 上限（包括提供方计入的推理 token）及底层网络操作超时 |
| `input_reservation_mode` | request_bytes | 纯文本按完整请求字节数加模板余量预留；不支持的格式退回完整上下文 |
| `candidate_timeout_seconds` | 600 | 每次训练/预测各 600 秒；独立预测沿用该 run 的资源快照 |
| `network_retry_attempts` | 2 | 同一逻辑请求最多额外重试 2 次，每次都单独预留、记账，可能重复收费 |
| `network_retry_backoff_seconds` | 30 | 两次重试分别退避 30、60 秒，与冷却等待重叠，不简单相加 |
| `network_cooldown_seconds` | 120 | 临时故障后暂停新派发；冷却后只放一个探测请求，成功后放开其他请求 |
| `max_unknown_calls` | 3 | 累计未决 unknown 达到 3 笔后拒绝新请求，不是连续失败次数；成功不会清零旧预留 |

超时、连接中断、HTTP 408/425/429/5xx 等可尝试有界恢复；鉴权错误、证书验证失败、非法 usage、返回模型不合规等不重试。单个逻辑请求重试耗尽且仍有恢复额度时，抛普通临时异常交由上游按原异常路径处理；永久预算不足、调用数、deadline 或未知阈值命中时停止所有新派发。暂时被在途预留占用的预算可等待结算再检查。已在途请求会排空并记账，因此未知最终笔数可能超过阈值，但预算预留仍在派发前原子检查。旧完整上下文模式单笔预留 1.179648 元，新运行默认采用下述请求级计算；预留不是确认扣款。

每次调度检查点保存 `checkpoint.json`、候选汇总及上游 journal。受控提前结束时，只要上游已经选出经可信执行验证的最佳节点，就冻结该节点并核验哈希；**不是保证任何失败都能产出模型**：初始化失败、始终没有有效候选、磁盘故障或强杀仍可能失败。检查点便于追溯，当前 CLI 不支持进程崩溃后的自动续跑，也不在外层跳过上游审查或重新选优。新策略尚未经过真实付费实验验证，不承诺运行满 8 小时或必得更高分。

当前实现及测试不等于所有模态已经通过真实任务评测；图像接口可接入，但尚未准备视觉预训练权重。当前状态统一维护在仓库根 README，关键工作历史在 journal.md，原始证据在 runs；不能把单元测试作为模型效果证据。

### 当前请求级预留

2026-11-19 的外层修正只影响新运行，不改上游算法或历史账本。共享及本机 runtime 均使用 `input_reservation_mode: request_bytes`，未写该项时也以此为默认；显式设为 `full_context` 可恢复旧算法。这里的“预留”始终是风险占用，不是学校账单。

- 普通纯文本消息在加入课程协议、schema 和实际 provider options 后，序列化完整 payload，计算 UTF-8 字节数 `B`、消息条数 `N`。输入上界取 `min(context_tokens_upper_bound, B + 4096 + 256 * N)`；预留费用为该输入上界与本次最大输出 token 按配置单价之和。每次实际派发和网络重试都原子检查、独立预留。
- 依据是 byte-level tokenizer 下每个文本 token 至少消耗一个字节，并为聊天模板预留余量；这不是学校提供方认证的 tokenizer 或隐藏模板上界。普通 `thinking.type=enabled/disabled`、`reasoning_effort` 可沿上游传递；图片、工具消息、不支持的字段或自定义 thinking budget 等退回完整上下文。未来接入新提供方时需要复核假设；不把此方法称为任意 API 下已证明的绝对上界。
- 正常返回按实际 usage 结算，释放差额；未知仍保留本次全部预留，不假定 504 免费。如果已返回的输入或输出 token 超过各自上界，记录真实账务后停止并要求核对，不能掩盖估计偏差。
- 若下一请求因在途预留占用预算而暂时无法派发，且在途请求释放余额后可能足够，抛 `BudgetPending` 供网关每 0.25 秒复查，不立即永久停止。等待遵守 deadline/停止信号，事件为 `budget_waiting` / `budget_resumed`。若结算加未知费用本身已不足、调用数或未知门槛命中，仍正常停止；不撤销旧 run 的停止状态，也不实现跨进程续跑。
- 对最近一轮全部 292 个已存请求仅做只读计算：新预留最小 0.138885 元、中位数 0.1804635 元、最大 0.231078 元；7 笔未知的假设预留合计 1.332104 元，对比旧实际预留 8.257536 元。285 个已有 usage 的响应均未超过新输入/输出上界。固定 0.15 元不能覆盖其中一些长请求，因此保留这个不新增依赖的动态计算。回放不修改旧账本，也不能证明新版能跑满 10 小时。
- WSL 专用环境完整 52 项离线测试通过，覆盖字节/模板/协议计数、格式回退、预算等待/结算恢复/未知转永久不足、deadline、上界超量停机及既有集成路径。本次没有新付费 API、搜索或最终 test，尚无新版真实长运行结果。
